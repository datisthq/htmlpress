Mintlify vs Htmlpress

Mintlify es una plataforma comercial de documentación. El contenido se redacta en MDX dentro de un repositorio Git; Mintlify aloja el sitio renderizado, la búsqueda y la analítica. El precio es por editor, con un plan gratuito para proyectos de código abierto.

De un vistazo

Aspecto Htmlpress Mintlify
Lenguaje / runtime Rust (binario único, sin runtime) Redacción en MDX; el runtime es el stack alojado de Mintlify (no público)
Framework de UI Ninguno (HTML + CSS plano, web components htmlpress-*) React (según la documentación de Mintlify)
Herramienta de compilación Binario de htmlpress CLI de Mintlify (vista previa) + compilación alojada
Formato de contenido Páginas HTML Markdown + MDX
Licencia MIT, autoalojado Propietaria, solo alojado
Modelo de salida Estático prerenderizado Alojado en la infraestructura de Mintlify

Arquitectura

htmlpress es un único binario de Rust que se instala desde npm (gethtmlpress), PyPI o crates.io. Envuelve cada página HTML en un layout con una navegación y un tema; no hay bundler, ni framework de UI, ni API de plugins. Cada archivo integrado (el layout, los estilos, los scripts y cada componente) se puede escapar: un archivo en la misma ruta bajo .htmlpress/ lo reemplaza. Tanto el código fuente como la salida son tuyos.

Mintlify es un SaaS alojado. Haces commit de MDX + un archivo de configuración mint.json a un repositorio Git; Mintlify lo descarga en cada push, lo compila y sirve el resultado desde <your-subdomain>.mintlify.app o un dominio propio. El pipeline de compilación y el runtime están gestionados y no se pueden instalar por tu cuenta.

En htmlpress la disposición del contenido no tiene restricciones: escanea por glob (include/exclude en htmlpress.yaml, todos los archivos .html por defecto), y la URL de una página sigue su ruta de archivo bajo la base del glob, así que docs/**/*.html sirve docs/guide.html en /guide.html. No hace falta una carpeta docs/. La navegación se construye a partir de las carpetas y del <meta name="order"> de cada página; el index.html de una carpeta da nombre a su grupo. Mintlify espera que el árbol de archivos coincida con el bloque navigation de mint.json; las rutas reflejan las rutas de archivo bajo la raíz de contenido configurada.

Superficie de contenido

Mintlify acepta Markdown + MDX con frontmatter e incrustación de componentes. Trae un conjunto fijo de componentes (<Card>, <Accordion>, <Tabs>, <Steps>, …) que los autores combinan en MDX. No escribes tus propios componentes de React para la UI de la documentación: usas las primitivas de Mintlify.

Las páginas de htmlpress son HTML semántico plano, al que el tema da estilo a partir de los propios elementos. Los bloques más ricos son elementos personalizados htmlpress-* (htmlpress-callout, htmlpress-tabs, htmlpress-steps, htmlpress-grid, …), cuyo CSS y JS se enlazan solo en las páginas que usan la etiqueta. Un proyecto añade su propia etiqueta con .htmlpress/components/<name>/<name>.html, que reemplaza la etiqueta en tiempo de compilación. Los integrados (htmlpress-grid + htmlpress-card, htmlpress-tabs, htmlpress-steps) producen el mismo tipo de UI y cada uno se puede escapar.

El mint.json de Mintlify configura la navegación, la marca y las integraciones en un único archivo declarativo. htmlpress usa htmlpress.yaml para los ajustes del sitio y el <head> de cada página para los suyos propios.

Salida y despliegue

htmlpress escribe cada página como HTML estático en .htmlpress/build/, junto con robots.txt, un sitemap.xml cuando site está definido, una copia en Markdown de cada página, llms.txt y las skills para agentes en .well-known/agent-skills/. La clave base sirve el sitio bajo una subruta. Consulta Despliegue para ver guías por hosting.

De los despliegues de Mintlify se encarga Mintlify. No compilas ni alojas la salida tú mismo; la plataforma sirve el sitio renderizado desde su CDN y gestiona TLS, dominios y vistas previas. Desvincularte de Mintlify implica reescribir el contenido o migrarlo a otro lugar.

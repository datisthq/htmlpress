Custom Routes

Articles are the pages include picks in htmlpress.yaml; they make the navigation. A route is a page of its own: any .html or .md file in .htmlpress/routes/ is served at the matching URL, no registration, no config change.

Minimal example

<!-- .htmlpress/routes/about.html -->
<title>About</title>

<htmlpress-header role="banner">
  <htmlpress-brand></htmlpress-brand>
  <htmlpress-theme-toggle></htmlpress-theme-toggle>
</htmlpress-header>
<main id="content">
  <h1>About</h1>
  <p>Anything you'd write in a normal HTML page, here.</p>
</main>
 
<!-- .htmlpress/routes/about.md -->
---
title: About
---

<htmlpress-header role="banner">
  <htmlpress-brand></htmlpress-brand>
  <htmlpress-theme-toggle></htmlpress-theme-toggle>
</htmlpress-header>

# About

Anything you'd write in a normal Markdown page, here.

Save and visit /about/. The header comes from the elements the route holds: htmlpress fills them as it fills a layout's.

Choosing the chrome

A route starts bare: no sidebar, header or footer is drawn around it until you add it. Compose as many layout elements as the page needs, anywhere in the route:

You put in the route You get
<htmlpress-brand> the site title, after the logo when set, linking home
<htmlpress-banner> the banner from htmlpress.yaml
<htmlpress-links> the header links
<htmlpress-nav> every page, grouped by top folder, then the sidebar links
<htmlpress-breadcrumbs> home, every folder above the page, then the page
<htmlpress-title> the page's leading <h1>, then its byline: authors, published and updated dates
<htmlpress-page-toc> the page's <h2> and <h3>
<htmlpress-pager> the previous and next pages
<htmlpress-edit> the "Edit on GitHub" link from edit
<htmlpress-toolbar> the page's actions: its source link and its Markdown copy, to view, copy or open in a chat
<htmlpress-footer> a "Created with Htmlpress" credit
<htmlpress-language> the language picker, on a site with translations
<htmlpress-shortcuts> the keyboard shortcuts menu, hidden on a phone
<htmlpress-skip> a "Skip to content" link to #content, in the page's language
none of them a blank page, all yours

The frame around them is elements too, never classes: <htmlpress-shell>, <htmlpress-sidebar>, <htmlpress-main>, <htmlpress-header>, <htmlpress-page> and <htmlpress-aside>; see Layout.

Htmlpress fills a route's <head> as it does every page's, so the theme, the site's metadata and the route's own head tags are always there. A landing page usually wants just the header, as in the example above. This site's home page is built this way.

How it fits with the rest of the site

  • File-based routing. A route's path under .htmlpress/routes/ is its URL, read as Livemark's TanStack file routes are, names kept as written: pricing.html is /pricing/, guide/faq.md and guide.faq.html are /guide/faq/, and an index or route file is served at its folder. A (group) or _pathless folder is left out of the URL, [.] is a literal dot, so feed[.]xml.html is served at /feed.xml, and a name starting with __ or holding a $param is no route.
  • The root path /. .htmlpress/routes/index.html is the home page, in place of an index.html article. A route's language is the prefix its URL is under, so es/index.html is the Spanish home page and its translation. Without one, the home page is the first article.
  • Routes win. A route takes the place of an article served at the same URL, and the build warns about it. Don't add one there unless you mean to hide the article.
  • Out of the navigation. A route is reached by its URL and by the links to it: the sidebar, the pager and search leave it out. It is still built with its Markdown copy and listed in the sitemap.
  • Partials. A file or folder whose name starts with -, such as -landing/hero.html, is no route: keep a route's parts there and place them with <htmlpress-include>.
  • Layouts still dress pages. An article or a route with <meta name="layout" content="wide"> takes .htmlpress/layouts/wide.html, whose <htmlpress-content> holds the page. A name is lowercase letters, digits and hyphens; a missing layout fails the build.
  • Not found. A 404.html at the root is the page a host shows for a missing URL; it is left out of the navigation, and a project without one gets a built-in "Page not found".

Importing htmlpress primitives

A route uses the same components htmlpress uses itself: any htmlpress-* component, built in or your own from .htmlpress/components/, renders the same way, linking its styles and scripts only where used. Style a route with its own components, as this site's home page does with its htmlpress-landing-* ones, or with the --htmlpress-* tokens. 

<!-- .htmlpress/routes/index.html -->
<title>Home</title>

<htmlpress-landing-hero></htmlpress-landing-hero>
<main id="content">…</main>
<htmlpress-footer></htmlpress-footer>

Static assets

Every file in the project that is not a page is copied to the output as-is, at the same path. Put a robots.txt, a custom favicon.svg, or an og-image.png beside your pages; a project file named like a generated one (robots.txt, sitemap.xml, llms.txt) wins over it.

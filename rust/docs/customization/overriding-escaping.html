Overriding/Escaping

Htmlpress ships a layout, a theme, two scripts and a library of components, all compiled into the binary. Every built-in file can be replaced: drop a file at the same path under .htmlpress/ and the build uses it instead.

To override Drop a file at
the page around the content .htmlpress/layout.html
the global theme .htmlpress/styles/<name>.css
a global script .htmlpress/scripts/<name>.js
one component .htmlpress/components/<tag>.css or .js
  • .htmlpress
    • layout.html
    • layouts
      • landing.html
    • styles
      • tokens.css
      • layout.css
      • content.css
    • scripts
      • code.js
    • components
      • htmlpress-callout.css
      • htmlpress-tabs.css
      • htmlpress-tabs.js
      • site-footer.html
layout.html
The page around the content, plain HTML with the layout elements htmlpress fills, such as <htmlpress-content> and <htmlpress-nav>.
styles/*.css
The global theme, joined into one theme.css on every page: tokens.css (the --htmlpress-* values), layout.css (the chrome around the page) and content.css (headings, prose, tables, code).
scripts/code.js
The copy button on code blocks and the link on each heading.
scripts/hints.js
The hover hint on abbreviations and footnote references.
components/<tag>.css and .js
One component each. Its styles sit in @scope (<tag>), so they never reach outside it, and its script defines only that element. A page links only the components it uses.

No other change is needed: the rest of htmlpress picks up the escaped file automatically.

The htmlpress escape command

htmlpress escape copies a default into .htmlpress/ to start from. Name a file by its path, or a component by its tag for all of its files: 

$ htmlpress escape                       # list every file, marking the escaped ones
$ htmlpress escape htmlpress-tabs        # its .css and .js
$ htmlpress escape layout.html styles/tokens.css
$ htmlpress escape htmlpress-tabs -r docs  # in another project folder

htmlpress escape never overwrites a file you already have: delete it first to start over. An escaped copy keeps the code it was copied from, so after an upgrade it misses the new defaults.

Deleting an escape restores the default: at once while htmlpress start runs, otherwise on the next start or build.

Example: custom footer

A file under components/ with a new tag adds a component of your own. Its .html replaces every <tag> in the layout and the pages at build time; its .css and .js load wherever the tag appears. 

<!-- .htmlpress/components/site-footer.html -->
<footer class="site-footer"><p>Built by my team · 2026</p></footer>

/* .htmlpress/components/site-footer.css */
@scope (.site-footer) {
  p { color: var(--htmlpress-muted); }
}

Then put <site-footer></site-footer> in an escaped layout.html or any page. Save: the dev server picks it up immediately. A tag needs a hyphen and lowercase letters, as every custom element does.

Example: retheme buttons

$ htmlpress escape components/htmlpress-button.css

Edit .htmlpress/components/htmlpress-button.css to change button styling everywhere: every page that uses <htmlpress-button> links your copy instead of the built-in one.

Example: tweak a token

$ htmlpress escape styles/tokens.css

Edit the :root block in .htmlpress/styles/tokens.css to rebrand: 

:root {
  --htmlpress-accent: oklch(0.55 0.24 27); /* red */
}

For a single page, override the token from that page's own <style> instead; no escape needed.

Using other components from an override

An escaped layout.html, a layout of your own and a component's .html may hold any htmlpress-* component, which renders and links its styles as it would in a page. A component's .html may not hold another project component's tag: it is pasted in once, never rewritten again.

Scoping a component's styles

A component's tag is gone once its .html replaces it, so the .css of a component with an .html scopes to a class on that markup, @scope (.site-footer), not to the tag. A component without an .html keeps its tag in the page and scopes to it, @scope (site-footer).

What you can't override this way

  • Layout element markup: the markup inside <htmlpress-nav>, <htmlpress-toc>, <htmlpress-pager> and the other layout elements is built from the site, so only their .css and .js can be escaped. A components/htmlpress-brand.html replaces one with your own static HTML.
  • Pages with a different layout: use .htmlpress/layouts/ instead.
  • The binary: reading pages, the navigation and the commands are not overridable; fork the repo if you need to change these.
  • Config schema: the shape of htmlpress.yaml is fixed.

The htmlpress- prefix is reserved. A file named for a tag htmlpress does not ship, such as htmlpress-calout.css, fails the build, and so does any file under styles/ or scripts/ that replaces nothing.

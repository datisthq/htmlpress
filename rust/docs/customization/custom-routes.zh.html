自定义路由

文章是 htmlpress.yaml 中 include 选中的页面，它们组成导航。路由则是独立的页面：.htmlpress/routes/ 中的任何 .html 或 .md 文件都在对应的 URL 上提供，无需注册，无需修改配置。

最小示例

<!-- .htmlpress/routes/about.html -->
<title>关于</title>

<htmlpress-header role="banner">
  <htmlpress-brand></htmlpress-brand>
  <htmlpress-theme-toggle></htmlpress-theme-toggle>
</htmlpress-header>
<main id="content">
  <h1>关于</h1>
  <p>在这里写任何你会写在普通 HTML 页面中的内容。</p>
</main>
 
<!-- .htmlpress/routes/about.md -->
---
title: 关于
---

<htmlpress-header role="banner">
  <htmlpress-brand></htmlpress-brand>
  <htmlpress-theme-toggle></htmlpress-theme-toggle>
</htmlpress-header>

# 关于

在这里写任何你会写在普通 Markdown 页面中的内容。

保存后访问 /about/。页眉来自路由中放置的元素：htmlpress 像填充布局的元素一样填充它们。

选择外观框架

路由从空白开始：在你添加之前，它周围不会绘制侧边栏、页眉或页脚。按页面需要在路由中的任意位置组合任意多个布局元素：

在路由中放入 得到
<htmlpress-brand> 站点标题（设置了 logo 时位于其后），链接到首页
<htmlpress-banner> htmlpress.yaml 中的 banner
<htmlpress-links> 页眉中的 links
<htmlpress-nav> 所有页面，按顶层文件夹分组，然后是侧边栏中的 links
<htmlpress-breadcrumbs> 首页、页面上层的每个文件夹，然后是页面本身
<htmlpress-title> 页面开头的 <h1>，然后是署名行：作者、发布日期和更新日期
<htmlpress-page-toc> 页面的 <h2> 和 <h3>
<htmlpress-pager> 上一页和下一页
<htmlpress-edit> 来自 edit 的"编辑此页"链接
<htmlpress-toolbar> 页面的 Markdown 副本，可查看、复制或在聊天中打开
<htmlpress-footer> "Created with Htmlpress" 署名
<htmlpress-language> 语言选择器，用于启用了翻译的站点
<htmlpress-shortcuts> 键盘快捷键菜单，在手机上隐藏
<htmlpress-skip> 指向 #content 的"跳到内容"链接，使用页面的语言
一个都不放 一个完全由你掌控的空白页面

包裹它们的框架同样是元素，而不是类： <htmlpress-shell>、<htmlpress-sidebar>、 <htmlpress-main>、<htmlpress-header>、 <htmlpress-page> 和 <htmlpress-aside>；参见 Layout。

Htmlpress 像填充每个页面一样填充路由的 <head>，因此主题、站点元数据和路由自身的 head 标签总是存在。落地页通常只需要页眉，就像上面的示例那样。本站的 首页 就是这样构建的。

与站点其余部分的配合

  • 基于文件的路由。路由在 .htmlpress/routes/ 下的路径就是它的 URL，按 Livemark 的 TanStack 文件路由规则读取，名称保持原样：pricing.html 是 /pricing/，guide/faq.md 和 guide.faq.html 都是 /guide/faq/，index 或 route 文件在其所在文件夹提供。(group) 或 _pathless 文件夹不计入 URL，[.] 是字面意义的点，因此 feed[.]xml.html 在 /feed.xml 提供；以 __ 开头或含有 $param 的名称不是路由。
  • 根路径 /。.htmlpress/routes/index.html 是首页，取代 index.html 文章。路由的语言取决于其 URL 所在的前缀，因此 zh/index.html 是中文首页，也是它的翻译。没有它时，首页是第一篇文章。
  • 路由优先。路由会取代同一 URL 上的文章，构建时会给出警告。除非你有意隐藏那篇文章，否则不要在那里添加路由。
  • 不在导航中。路由只能通过其 URL 和指向它的链接访问：侧边栏、翻页器和搜索都不包含它。它仍会连同 Markdown 副本一起构建，并列入站点地图。
  • 片段。名称以 - 开头的文件或文件夹，例如 -landing/hero.html，不是路由：把路由的组成部分放在那里，并用 <htmlpress-include> 放置它们。
  • 布局仍可装扮页面。带有 <meta name="layout" content="wide"> 的文章或路由使用 .htmlpress/layouts/wide.html，其中的 <htmlpress-content> 容纳页面。名称由小写字母、数字和连字符组成；缺少布局会导致构建失败。
  • 未找到。根目录下的 404.html 是主机在 URL 不存在时显示的页面；它不出现在导航中，没有它的项目会得到内置的“页面未找到”。

引入 htmlpress 基础组件

路由使用与 htmlpress 自身相同的组件：任何 htmlpress-* 组件，无论是内置的还是你在 .htmlpress/components/ 中的，都以相同方式渲染，并只在使用的地方链接其样式和脚本。用路由自己的组件为它设置样式，就像本站首页使用它的 htmlpress-landing-* 组件那样，或者使用 --htmlpress-* 令牌。 

<!-- .htmlpress/routes/index.html -->
<title>Home</title>

<htmlpress-landing-hero></htmlpress-landing-hero>
<main id="content">…</main>
<htmlpress-footer></htmlpress-footer>

静态资源

项目中所有不是页面的文件都会按原样复制到输出目录的相同路径下。把 robots.txt、自定义的 favicon.svg 或 og-image.png 放在页面旁边即可；与生成文件同名的项目文件（robots.txt、sitemap.xml、llms.txt）会优先于生成的文件。

另请参阅

  • 覆盖/弹出：替换站点的布局或组件，而不是绘制一个自己的页面。
  • 站点元数据：同样显示在自定义路由上的站点标题和 favicon。

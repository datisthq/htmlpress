Agent Skills

Htmlpress ships an Agent Skill that tells coding agents such as Claude Code, Cursor and Codex how an htmlpress project works. Once installed, your agent knows the page contract, which components exist, which config keys are allowed, how to escape the layout and how to check its work. You don't have to explain any of it in the prompt.

Htmlpress keeps an agent's job small: write semantic HTML, use a component only where HTML has none, and leave the styling to the theme. The fewer choices a page offers, the more pages look like one site.

Skill Your agent uses it when
htmlpress-pages writing or editing pages, components, htmlpress.yaml and escapes, and checking the result

Install from the website

htmlpress.dev publishes its skills under /.well-known/agent-skills/, so the skills CLI can install them from the site URL. Run this at your project root: 

npx skills add https://htmlpress.dev

It asks which skills and agents to install for. To skip the prompts, pass them as flags: 

npx skills add https://htmlpress.dev --skill htmlpress-pages --agent claude-code

Add --global to install for your user instead of the project, and --list to see what's available without installing anything. Run npx skills update later to pull newer versions.

Install from the package

The skill is not yet bundled in the npm, PyPI or crates.io packages. Until it is, install it from the website, or copy it from .skills/ in the repository.

Use them

You don't need to invoke a skill yourself. Agents read each skill's description and load it when a task matches: asking for a new page or a change to the site's look loads htmlpress-pages. If your agent supports invoking skills by name, you can also call one directly, as with /htmlpress-pages in Claude Code.

The loop

  1. Run htmlpress --llms once to learn the commands.
  2. Write or edit pages in the project folder.
  3. Run htmlpress build <root> --json and read pages and any error on stderr.
  4. For a visual check, run htmlpress start <root> and open the page in a browser.

Rules worth giving an agent

  • One <title> and one <h1> per page; a <meta name="order"> where navigation order matters.
  • No inline style, no classes for looks: override a --htmlpress-* token instead.
  • Only the documented components; anything else is plain HTML.
  • Never edit .htmlpress/build.

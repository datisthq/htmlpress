Write semantic HTML pages, or let your agent write them. Htmlpress adds one layout, one theme, a navigation and a live-reloading dev server, and every part of it can be escaped.

Stays out of your way

No framework, no build config, no required structure. A folder of HTML is already a project.

  • Any folder of HTML

    A page is any .html file, a full document or a bare fragment. Folders become navigation groups, and every other file is copied as it is.

  • Your own components

    A file in .htmlpress/components/ names a new tag: its HTML is pasted in, its CSS and JS load only on the pages that use it.

  • Escape anything

    Replace the layout, the theme or any built-in component from .htmlpress/, or give one page its own layout. This landing page is one.

Beautiful by default

A polished theme, the components docs need and sensible defaults. Customize only what you want.

Styled from the elements

Headings, lists, tables, code, <details>, <figure> and <kbd> look right with no classes at all.

Components where HTML has none

Callouts, tabs, steps, cards, file trees, badges, sortable tables and zoomable images, as light-DOM custom elements.

Readable before the script

Every component leaves plain HTML in place, so a page reads well before any script loads, and to any agent that fetches it.

Navigation from the folder

Grouped by folder, ordered by <meta name="order">, with a table of contents and previous and next links.

At home on a phone

The navigation turns into a drawer, the table of contents steps aside, and nothing scrolls sideways.

Dark mode and theme tokens

A dark theme from the system or the toggle, and every color, font and width a --htmlpress-* token.

Live reload

htmlpress start rebuilds on every save and reloads the browser, escapes and components included.

Static output

htmlpress build writes plain files to .htmlpress/build, with canonical links, ready for any static host.

One binary, three channels

A single Rust executable, installed from npm, PyPI or crates.io. Nothing else to install.

Made for coding agents

Agents know HTML better than any templating language. Htmlpress keeps their job small and every answer machine-readable. 

$ htmlpress build docs --json
{
  "output": "docs/.htmlpress/build",
  "pages": 8,
  "files": 12
}

$ htmlpress build --json '{"root":"docs","out":"dist"}'

$ htmlpress --llms

  • Plain semantic HTML in

    No framework, no syntax to learn, no utility classes: the fewer choices a page offers, the more pages look like one site.

  • Every command speaks JSON

    --json prints the result on stdout and takes the input as JSON; logs and errors go to stderr.

  • The CLI in one read

    htmlpress --llms lists every command's input and output schema as MCP-shaped tools.

  • A Markdown copy of every page

    Each page gets an index.md beside its HTML, linked from the page head, so an agent reads the content without the markup.

  • llms.txt out of the box

    An llms.txt index of every copy, grouped as the navigation groups them and advertised in a Link header on the home page.

  • A skill for your agent

    Five skills teach Claude Code, Cursor or Codex to write, configure, restyle and deploy a site.

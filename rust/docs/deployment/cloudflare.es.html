Cloudflare

Cloudflare Workers puede servir directamente un directorio de assets estáticos: sin cómputo aparte ni shim de SPA. Así se publica htmlpress.dev, y la misma estructura de wrangler.jsonc sirve para cualquier sitio htmlpress. Los assets estáticos de Workers también leen el archivo _headers que escribe cada compilación.

Compila el sitio

htmlpress build

La salida queda en .htmlpress/build/.

Configura wrangler.jsonc

Coloca esto en la raíz de tu proyecto:

{
  "name": "my-docs",
  "compatibility_date": "2026-04-01",
  "workers_dev": true,
  "assets": {
    "directory": ".htmlpress/build",
    "html_handling": "none",
    "not_found_handling": "404-page",
  },
}

Cuatro campos hacen el trabajo pesado:

Campo Propósito
assets.directory Apunta Wrangler a la salida de compilación de htmlpress. Cada archivo se sirve tal cual.
assets.html_handling Sirve cada archivo en su propia ruta. El valor por defecto redirige /guide.html a /guide, lejos de las URLs a las que enlaza htmlpress y que coincide la regla de Markdown de más abajo.
assets.not_found_handling Responde a las rutas desconocidas con el 404.html de la compilación.
workers_dev Te da una URL de previsualización <name>.<account>.workers.dev mientras haces pruebas.

Despliega desde tu máquina

htmlpress build
npx wrangler deploy

La primera ejecución te pide wrangler login para autorizar el acceso a tu cuenta de Cloudflare.

Despliega con GitHub Actions

name: deploy

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-node@v4
        with:
          node-version: 24
      - run: npx gethtmlpress build
      - uses: cloudflare/wrangler-action@v3
        with:
          apiToken: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          accountId: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}

Crea un token de API con alcance limitado en My Profile → API Tokens (la plantilla "Edit Cloudflare Workers" concede exactamente lo que necesitas) y guarda ambos valores como secretos del repositorio.

Sin un workflow, Workers Builds puede ejecutar la compilación por sí mismo: conecta el repositorio en el panel y añade un bloque build a wrangler.jsonc, como hace htmlpress.dev con "build": { "command": "pnpm build:docs" }.

Dominio personalizado

Añade un bloque routes cuando tu zona esté en Cloudflare:

{
  "name": "my-docs",
  "compatibility_date": "2026-04-01",
  "assets": { "directory": ".htmlpress/build", "not_found_handling": "404-page" },
  "routes": [{ "pattern": "docs.example.com", "custom_domain": true }],
}

custom_domain: true indica a Cloudflare que aprovisione un dominio gestionado: DNS, certificado y ruta se encargan por ti. Define site con el mismo dominio en htmlpress.yaml para que las URLs absolutas del sitemap coincidan.

El propio wrangler.jsonc del repositorio de htmlpress es una referencia funcional; consulta la raíz del proyecto.

Markdown para agentes

Los agentes de IA piden una página en Markdown enviando Accept: text/markdown. Los assets estáticos siempre responden con HTML, así que añade a tu zona una URL Rewrite Rule que dirija esas peticiones a la copia en Markdown de la página: guides/build.html tiene guides/build.md a su lado. Las URL Rewrite Rules están disponibles en todos los planes, incluido Free, y el sitio sigue siendo totalmente estático.

En el panel, abre tu dominio, ve a Rules → Overview → Create rule → URL Rewrite Rule y rellena:

Campo Valor
Rule name Markdown for agents
If incoming requests match Custom filter expression (abajo)
Path Rewrite to → Dynamic → wildcard_replace(http.request.uri.path, "*.html", "${1}.md")
Query Preserve 
any(http.request.headers["accept"][*] contains "text/markdown") and ends_with(http.request.uri.path, ".html")

Las URLs de página terminan en .html, así que la regla solo afecta a las páginas. Para URLs de carpeta como /guides/, añade una segunda regla que coincida con ends_with(http.request.uri.path, "/") y reescriba a concat(http.request.uri.path, "index.md"). Los assets estáticos sirven los archivos .md como text/markdown, así que el tipo de respuesta no necesita ninguna regla adicional.

Despliega una compilación que contenga las copias en Markdown antes de activar la regla. De lo contrario, un agente que pida Markdown recibirá un 404.

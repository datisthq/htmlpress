Despliegue

htmlpress build genera un sitio completamente estático en .htmlpress/build/: un archivo .html por cada página en la misma ruta que su fuente, un 404.html, robots.txt, un sitemap.xml (cuando site está definido), un archivo _headers, las copias en Markdown y llms.txt para agentes, los scripts del tema y de los componentes en _htmlpress/, y todos los demás archivos del proyecto. Sube ese directorio a cualquier host estático y tu sitio estará en línea.

Estas guías recorren los destinos más habituales. Elige uno: cada guía es autónoma y muestra tanto el comando manual como un workflow de CI.

Hosts

Hosting estático

Cualquier host que sirva un directorio de archivos: nginx, S3 + CloudFront, Caddy y similares.

GitHub Pages

Gratuito, nativo de git y adecuado para sitios de proyecto bajo una ruta /repo-name/.

Cloudflare

Workers + assets estáticos. La configuración que usa el propio htmlpress.dev.

Vercel

Conectado a git, con previsualizaciones por pull request y dominios sin configuración.

Netlify

Conectado a git, con despliegues por rama, publicaciones atómicas y gestión de formularios integrada.

Qué asume cada guía

  • Ejecutas htmlpress build en la raíz del proyecto y la salida queda en .htmlpress/build/. En CI, npx gethtmlpress build ejecuta el mismo binario sin instalarlo antes; consulta Introducción para los demás canales.
  • Has definido site en htmlpress.yaml si quieres sitemap.xml, la línea del sitemap en robots.txt, URLs canónicas y etiquetas sociales absolutas; consulta Metadatos del sitio.
  • Solo necesitas base si tu sitio se monta bajo una subruta (p. ej., los sitios de proyecto de GitHub Pages). La guía de GitHub Pages es la única que lo cubre.

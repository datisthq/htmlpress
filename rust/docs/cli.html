CLI

htmlpress build [root]

Renders the project at root (default .) into root/.htmlpress/build, replacing what is there. --out / -o picks another folder; one that would hold the project, or a visible folder inside it, is refused, since its pages would be read back as sources. 

$ htmlpress build docs
built 6 pages and 0 files into docs/.htmlpress/build

htmlpress start [root]

Builds the project, serves it on http://localhost:8000 and rebuilds on every change. Open pages reload themselves after each build. A broken page prints its error and keeps the last good build up.

When 8000 is taken it tries 8001 and on to 8009, and prints the URL it got. --port / -p names one port instead (0 picks any free one). --host alone serves on every address, so a phone on the same network can open the site, and prints that URL too; --host <address> serves on one. With base in htmlpress.yaml the site is served under it, the printed URLs include it, and / leads there; restart after changing base. 

$ htmlpress start docs --host
serving http://localhost:8000
network http://192.168.1.107:8000

htmlpress preview [root]

Builds the project for production and serves it as it will be deployed: no watching, no reload. Takes --port, --host and --out like start.

htmlpress clear [root]

Removes the build output (--out to name another), with the same guard as build.

htmlpress escape [names…]

Copies built-in files into .htmlpress/ to edit them: a name is a path such as components/htmlpress-tabs.js, or a component's tag for all its files. Without names it lists every built-in file and whether the project has escaped it. --root / -r picks the project (default .). It refuses to overwrite a file; see Escaping. 

$ htmlpress escape htmlpress-tabs
escaped .htmlpress/components/htmlpress-tabs.css
escaped .htmlpress/components/htmlpress-tabs.js

For scripts and agents

The CLI is built with Fireargs, so every command speaks JSON. --json prints the result as JSON, and with a value it also takes the input as JSON: 

$ htmlpress build docs --json
{
  "output": "docs/.htmlpress/build",
  "pages": 6,
  "files": 0
}
$ htmlpress build --json '{"root":"docs","out":"dist"}'

htmlpress --llms prints every command's input and output schema as an MCP-shaped tool list, so an agent learns the CLI without reading this page.

Frontmatter

A page has no YAML frontmatter: its metadata is the HTML <head> itself. A page is a full document or a fragment, and htmlpress reads both the same way. Every tag is optional; htmlpress derives sensible defaults from the file when one is missing. 

<title>Getting started</title>
<meta name="description" content="Install and run it.">
<meta name="order" content="1">

<h1>Getting started</h1>
<p>Plain HTML, styled by the theme.</p>

The body becomes the page's content inside the layout. Give every page one <title> and one <h1>.

Article metadata

Identity and presentation of the page.

Tag Default Purpose
<title> first <h1>, else the file name Names the page in the navigation and the browser tab.
<meta name="description"> description from htmlpress.yaml The page's description for search engines and social previews.
<meta name="image"> none The image shown when the page is shared, as og:image; a root-relative URL is made absolute with site.
anything else in <head> none Kept: a page's own <link>, <style> or <script> is added to the layout's head, after the theme.
<meta name="date"> none When the page was published, YYYY-MM-DD (a timestamp is cut to its date; anything else is an error). Shown under the title, and it sorts a blog.
<meta name="author"> none An author shown under the title; repeat the tag for several.
<meta name="keywords"> none Comma-separated tags; in a blog each gets a page listing its posts.

The line under the page's <h1> also says when its file last changed, from git log, when the project is in a git repository; the same date is the page's <lastmod> in sitemap.xml.

Sidebar settings

How the page shows up in the navigation.

Tag Default Purpose
<meta name="order"> none (sorted by path) An integer sort position; see "Ordering rules" below.
<meta name="layout"> the site's layout Wraps the page in .htmlpress/layouts/<name>.html instead, for a page that wants different chrome, such as a landing page without the sidebar. A missing layout fails the build; see Overriding and Escaping.
<meta name="label"> the title A shorter name for the page's navigation entry.
<meta name="icon"> none A built-in icon before a top-level navigation entry, or a folder's group for its index page; pages inside a folder show none. An unknown name fails the build.
<meta name="sidebar" content="false"> true Leaves the page out of the navigation and the previous and next links; it is still built and reachable by its URL.
<meta name="toc" content="false"> true Turns off the page's table of contents.
<meta name="source-url"> edit followed by the page's path Where the page's source link leads, for a page whose source lives elsewhere; <meta name="source-action" content="view"> labels it "View source" instead of "Edit this page".

Ordering rules

  • The root index.html always leads.
  • Pages with an order of 0 or more come next, ascending.
  • Pages without one follow, by path.
  • Pages with a negative order come last, so -1 pins a page to the very end and -2 sits just before it.

The order places a page among its siblings: pages nest under their folder's index.html, and a folder sits where its first page would.

An order that is not an integer fails the build. A 404.html at the root is the page a host shows for a missing URL; it is left out of the navigation, and a project without one gets a built-in "Page not found".

URL

A page is written to the same path it was read from, and index.html is served at its folder: guides/index.html at /guides/. See Links.

<meta name="path" content="/start/"> serves the page at another URL, independent of its file path: a path ending in / is built to that folder's index.html, one ending in .html to that file. Two pages on one URL fail the build.

On a site with languages, a file named guide.es.html, or one with <meta name="language" content="es">, is the Spanish translation of guide.html, served at /es/guide.html; see Translations.

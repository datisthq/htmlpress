Rich Elements

A few htmlpress-* elements cover what HTML has no element for. They are light-DOM custom elements, so their content stays plain HTML that reads well even before the script loads. Each one's styles and script are linked only on pages that use it. Put block content (<p>, <h3>, <pre>) inside a component, not bare text.

Tables

A plain <table> is styled as it is. Wrap one that has a <thead> in <htmlpress-table> and a click on any header sorts by it: 

<htmlpress-table>
  <table>
    <thead><tr><th>Language</th><th>Year</th><th>Typing</th></tr></thead>
    <tbody><tr><td>TypeScript</td><td>2012</td><td>Static</td></tr>…</tbody>
  </table>
</htmlpress-table>

Renders as:

Language Year Typing
TypeScript 2012 Static
Python 1991 Dynamic
Rust 2010 Static
JavaScript 1995 Dynamic

Callouts

Callouts highlight important information. type is info (the default), success, warning or danger, and label replaces the heading the type gives: 

<htmlpress-callout><p>This is a note.</p></htmlpress-callout>

<htmlpress-callout type="warning" label="Breaking Change">
  <p>This API has been removed in v2.</p>
</htmlpress-callout>

Renders as:

This is a note.

Every page built.

Be careful with this.

Never edit .htmlpress/build: every build replaces it.

This API has been removed in v2.

Headings inside a callout stay out of the page's table of contents.

Expandable

No component needed: the theme styles a plain <details>.

<details>
  <summary>Click to expand</summary>
  <p>Hidden content here with <strong>HTML</strong> support.</p>
</details>

Renders as:

Click to expand

Hidden content here with HTML support.

You can nest any HTML inside, including code blocks, lists and callouts:

Configuration example 
site: https://htmlpress.dev

Code Tabs

Tabs that hold only code blocks join into one framed block. Each <section> is a tab, named by its title: 

<htmlpress-tabs sync="lang">
  <section title="JavaScript"><pre><code>console.log("hello")</code></pre></section>
  <section title="Python"><pre><code>print("hello")</code></pre></section>
</htmlpress-tabs>

Renders as:

console.log("hello")
print("hello")

Add sync="key" to keep tab groups in sync, as described under Content Tabs below.

Content Tabs

Group arbitrary content into tabs with <htmlpress-tabs>, one <section title> per tab.

Add a sync attribute to synchronize tab selection across tab groups. When a reader selects a tab in one group, every other group with the same sync key switches to the matching tab, and the choice is remembered across pages in localStorage. 

<htmlpress-tabs sync="channel">
  <section title="cargo"><p>From crates.io, built on your machine.</p></section>
  <section title="npm"><p>A prebuilt binary per platform.</p></section>
  <section title="pip"><p>A binary wheel.</p></section>
</htmlpress-tabs>

Renders as (both groups share sync="channel"; switch one):

cargo install htmlpress
npm install -g gethtmlpress
pip install htmlpress

From crates.io, built on your machine.

A prebuilt binary per platform.

A binary wheel.

Steps

An <ol> inside <htmlpress-steps> is a numbered guide, one step per <li>, each led by an <h3>. Those headings stay out of the page's table of contents. 

<htmlpress-steps>
  <ol>
    <li><h3>Install</h3><p>…</p></li>
    <li><h3>Write a page</h3><p>…</p></li>
  </ol>
</htmlpress-steps>

Renders as:

  1. Install

    Pick a channel from the tabs above.

  2. Write a page

    Any .html file in the folder.

  3. Start

    Run htmlpress start and open the URL it prints.

Cards

Cards in <htmlpress-grid> fill responsive columns; cols fixes their number from 2 to 4, and narrow screens fall back to one. A link in a card's heading makes the whole card clickable. 

<htmlpress-grid cols="2">
  <htmlpress-card>
    <h3><a href="/introduction.html">Getting Started</a></h3>
    <p>Learn how to set up your first project.</p>
  </htmlpress-card>
  <htmlpress-card><h3>Plain HTML</h3><p>…</p></htmlpress-card>
</htmlpress-grid>

Renders as:

Getting Started

Learn how to set up your first project.

Configuration

Configure your htmlpress project.

GitHub

View the source code on GitHub.

Plain HTML

A card without a link is not clickable.

Headings inside a card stay out of the page's table of contents.

Badges

An inline label. type is info, success, warning, danger or neutral; without it, the accent. 

<htmlpress-badge>New</htmlpress-badge>
<htmlpress-badge type="success">Stable</htmlpress-badge>

Renders as: New Info Stable Beta Removed v1

Buttons

A link inside <htmlpress-button> is a call to action; type="secondary" makes it quieter. 

<htmlpress-button><a href="/introduction.html">Get Started</a></htmlpress-button>
<htmlpress-button type="secondary"><a href="…">GitHub</a></htmlpress-button>

Renders as:

Get Started GitHub

Icons

A built-in icon set for inline icons. Until then, an inline <svg> is plain HTML like any other.

File Tree

A nested list inside <htmlpress-file-tree>; an item holding a list is a folder. 

<htmlpress-file-tree>
  <ul>
    <li>docs<ul><li>index.html</li></ul></li>
    <li>htmlpress.yaml</li>
  </ul>
</htmlpress-file-tree>

Renders as:

  • docs
    • index.html
    • guides
      • build.html
  • htmlpress.yaml

</htmlpress-grid>

Theme tokens

Colors, fonts and widths are CSS custom properties on :root, with a dark set under prefers-color-scheme or the header's theme toggle: --htmlpress-accent, --htmlpress-accent-text, --htmlpress-bg, --htmlpress-surface, --htmlpress-text, --htmlpress-muted, --htmlpress-border, --htmlpress-info, --htmlpress-success, --htmlpress-warning, --htmlpress-danger, --htmlpress-font, --htmlpress-mono, --htmlpress-radius, --htmlpress-shadow, --htmlpress-width and --htmlpress-nav-width. Override them from a page's own stylesheet: 

:root {
  --htmlpress-accent: oklch(0.6 0.18 30);
  --htmlpress-font: "Inter", system-ui, sans-serif;
  --htmlpress-width: 52rem;
}

Layout

The layout is plain HTML. Htmlpress fills its <head> (charset, viewport, title, description, social preview tags, canonical link, favicon, the theme, the styles and scripts of the components the page uses, the head tags from htmlpress.yaml, then the page's own head tags) and replaces these elements at build time:

<htmlpress-content>
The page's content.
<htmlpress-brand>
The site title, after the logo when set, linking home.
<htmlpress-banner>
The banner from htmlpress.yaml.
<htmlpress-breadcrumbs>
Home, every folder above the page (named and linked by its index page when it has one), then the page.
<htmlpress-nav>
The open section's pages (every page without sections), grouped by top folder; a folder's group is named by its index page. The sidebar sections open it and the sidebar links close it.
<htmlpress-links>
The header sections, the open one marked, then the header links from htmlpress.yaml.
<htmlpress-toc>
The page's <h2> and <h3>, highlighting the one in view. A heading without an id gets one from its text.
<htmlpress-pager>
The previous and next pages in navigation order.
<htmlpress-edit>
An "Edit this page" link from edit in htmlpress.yaml.
<htmlpress-toolbar>
A link to the page's Markdown copy; the script adds "Copy Markdown", "Open in ChatGPT" and "Open in Claude".
<htmlpress-footer>
A "Created with Htmlpress" credit.

An element with nothing to show is removed. <htmlpress-nav-toggle>, <htmlpress-theme-toggle> and <htmlpress-back-to-top> are built by the script in the browser. A .htmlpress/layout.html in the project replaces the built-in layout, and a page can pick its own from .htmlpress/layouts/. Every component's styles and script can be replaced or added the same way: see Overriding and Escaping.

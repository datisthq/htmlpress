Advanced Syntax

HTML Blocks

A page is HTML, so every element works directly. Common examples include <kbd> for keyboard shortcuts, <sup>/<sub> for superscripts and subscripts, and <details>/<summary> for accordions. 

Press <kbd>Ctrl</kbd> + <kbd>C</kbd> to copy. Water is H<sub>2</sub>O.

Renders as: Press Ctrl + C to copy. Water is H2O.

Prefer semantic elements to classes and inline style: the theme styles the elements themselves, and that is what keeps every page looking like the same site. To change the look site-wide, override a theme token instead.

MDX Rendering

There is no templating language: what a page needs beyond HTML comes from its own <head>. A page's <link>, <style> and <script> are kept and added to the layout's head, after the theme: 

<title>Version</title>
<script type="module">
  document.querySelector("#version").textContent = "2.0.0"
</script>

<h1>Version</h1>
<p>The current version is <strong id="version"></strong>.</p>

This is an escape hatch for advanced use cases. For markup shared between pages, use a project component.

LaTeX Expressions

LaTeX math rendered at build time. Until then, MathML is plain HTML that browsers draw natively. 

<math><mi>E</mi><mo>=</mo><mi>m</mi><msup><mi>c</mi><mn>2</mn></msup></math>

Renders as: E = m c2

Mermaid Diagrams

A <pre> inside <htmlpress-mermaid> holds Mermaid source, drawn in the current theme and redrawn when the theme changes. Escape < and & in the source. The library loads from jsDelivr only on a page that has a diagram; offline, the source shows instead. 

<htmlpress-mermaid>
  <pre>flowchart LR
  pages[HTML pages] --&gt; build[htmlpress build] --&gt; site[Static site]</pre>
</htmlpress-mermaid>

Renders as:

flowchart LR
  pages[HTML pages] --> build[htmlpress build] --> site[Static site]
 
<htmlpress-mermaid>
  <pre>pie title Languages
  "Rust" : 45
  "TypeScript" : 30
  "Python" : 15
  "Other" : 10</pre>
</htmlpress-mermaid>

Renders as:

pie title Languages
  "Rust" : 45
  "TypeScript" : 30
  "Python" : 15
  "Other" : 10

Included Documents

A project component shares markup between pages. A file at .htmlpress/components/<name>/<name>.html fills every <htmlpress-<name>> in every page at build time:

  • .htmlpress
    • components
      • disclaimer
        • disclaimer.html
        • disclaimer.css
  • guide.html
 
<!-- .htmlpress/components/disclaimer/disclaimer.html -->
<aside><p>Provided as-is, without warranty.</p></aside>

<!-- guide.html -->
<htmlpress-disclaimer></htmlpress-disclaimer>
  • Its .css and .js load only on pages where the tag appears; the tag stays around the pasted markup, so its CSS scopes to the tag, @scope (htmlpress-disclaimer).
  • The folder is the tag without its htmlpress- prefix, the same as a built-in's: a folder named for a built-in component, such as tabs, replaces it.

See Overriding and Escaping for every file under .htmlpress/.

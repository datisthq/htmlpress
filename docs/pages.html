Pages

A project is a folder. Every .html file in it is a page, and every other file is copied to the output as-is, at the same path. Dot-folders such as .git/ and .htmlpress/, and node_modules/, are skipped.

A page

A page is a full document or a fragment; htmlpress reads both the same way:

<title>Getting started</title>
<meta name="description" content="Install and run it.">
<meta name="order" content="1">

<h1>Getting started</h1>
<p>Plain HTML, styled by the theme.</p>
<title>
Names the page in the navigation and the browser tab. Without one, the first <h1> does, and without that the file name.
<meta name="description">
The page's description for search engines; the site's from htmlpress.yaml otherwise.
<meta name="image">
The image shown when the page is shared, as og:image; a root-relative URL is made absolute with site.
<meta name="order">
An integer that sorts the navigation, lower first. index.html always leads, ordered pages follow, the rest by path.
<meta name="layout">
Wraps the page in .htmlpress/layouts/<name>.html instead of the site's layout, for a page that wants different chrome, such as a landing page without the sidebar. See Escaping.
Anything else in <head>
Kept: a page's own <link>, <style> or <script> is added to the layout's head, after the theme.
The body
Becomes the page's content inside the layout. Every <h2> and <h3> without an id gets one from its text, and those outside a component make the page's table of contents.

A 404.html at the root is the page a host shows for a missing URL; it is left out of the navigation, and a project without one gets a built-in "Page not found".

URLs and links

A page is written to the same path it was read from, so relative links between pages keep working. index.html is served at its folder: guides/index.html at /guides/.

The navigation groups pages by their top folder, named by the folder's index.html title, else the folder's name. Pages at the root come ungrouped.

With base set, every root-relative URL in the build (in href, src, srcset, poster and action, in pages, the layout and the config's HTML alike) gets it as a prefix: write /guide.html and the site links to /repo/guide.html. Relative and absolute URLs are left alone, and so are url()s in a page's own CSS. start and preview serve the site under the base too, and send / there.

Configuration

An optional htmlpress.yaml at the project root sets the site. Its keys follow Livemark's config: 

site: https://htmlpress.dev
title: Htmlpress
description: Turn a folder of HTML pages into a site.
logo: /logo.svg
banner: 'Version 1 is out: <a href="/changelog.html">read more</a>'
links:
  - title: GitHub
    url: https://github.com/datisthq/htmlpress
  - title: Chat
    url: https://discord.gg/example
    position: sidebar
head:
  scripts:
    - src: https://stats.example.com/script.js
      defer: ""
contentSignals:
  aiTrain: false
edit: https://github.com/datisthq/htmlpress/edit/main/docs/
Key Default Use
site none the public URL, for canonical and social links and sitemap.xml
base none the sub-path the site is served under, such as /repo/ on GitHub Pages; see URLs and links
title the folder name the header and every tab title
description none for pages without their own
logo none an image's URL, shown before the site title
favicon the logo the site icon's URL
banner none HTML for an announcement bar above the header
links none links, each a title, a url and a position: header (default) or sidebar
head none meta, links and scripts: lists of attribute maps added to every page's head; a script's children is its inline source, and a meta sharing a built-in one's name or property replaces it
contentSignals all true search, aiInput and aiTrain: how automated systems may use the content, written to robots.txt
include **/*.html one glob or a list: the .html files that become pages. It replaces the default, so list every folder you want. Each glob's folders before its first wildcard are its base: only files under a base are read, and they are served without it, so docs/**/*.html builds docs/guide.html to /guide.html. Other files under a base, .html ones include leaves out too, are copied as they are
exclude none one glob or a list: files left out of the build entirely, pages or not
skills none one glob or a list of SKILL.md files, relative to the project, to publish for agents (see Agents)
edit none an "Edit this page" link: this URL followed by the page's path

An unknown key is an error, so a typo never passes silently. Globs are relative to the project: * stays within a folder, ** crosses folders, and an include or exclude pattern that matches no file prints a warning.

Every build writes a robots.txt, when site is set a sitemap.xml of every page, and the files for agents on the Agents page; a project file of the same name wins, except _headers, whose rules are kept and extended.

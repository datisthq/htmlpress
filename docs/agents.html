Agents

Htmlpress keeps an agent's job small: write semantic HTML, use a component only where HTML has none, and leave the styling to the theme. The fewer choices a page offers, the more pages look like one site.

The loop

  1. Run htmlpress --llms once to learn the commands.
  2. Write or edit pages in the project folder.
  3. Run htmlpress build <root> --json and read pages and any error on stderr.
  4. For a visual check, run htmlpress start <root> and open the page in a browser.

Rules worth giving an agent

  • One <title> and one <h1> per page; a <meta name="order"> where navigation order matters.
  • No inline style, no classes for looks: override a --htmlpress-* token instead.
  • Only the documented components; anything else is plain HTML.
  • Never edit .htmlpress/build.

What a site publishes for agents

Every build also writes the site in the form agents read best, beside the HTML:

A Markdown copy of each page
guides/build.html gets guides/build.md: its title, description and content, with each component reduced to plain Markdown (a callout to a quote, tabs to bold headings). Each page links it from its head as rel="alternate".
llms.txt
The site title and description, then every page's Markdown copy with its description, grouped as the navigation groups them. A project without an index.html gets it as index.md too.
Agent skills
The SKILL.md files the skills key matches, each with a frontmatter name and description, under .well-known/agent-skills/ with an index.json that lists them with a digest.
_headers
For Cloudflare and Netlify: a Link on the home page pointing at llms.txt, index.md and the skills index.

The page toolbar beside each page links its Markdown copy and, with the script, copies it or opens the page in ChatGPT or Claude.

The htmlpress skill

The repository ships these as an agent skill, htmlpress-pages, in .skills/, and this site publishes it at /.well-known/agent-skills/.
